# `index.*.md` 与 `index.en.*.md` 评审

## 结论先行

- **中文最有人味、最像博客复盘：`index.o55.2.md`。** 它把“我当时怎么判断、哪里判断错、为什么不敢继续替换”写出来了，技术细节也没有明显缩水。
- **中文最符合 `spec.md` 的完整度：`index.1017.md`。** 结构完整，推断与证据分得较清楚，叙述克制，更新批评还保留了来源链接。
- **英文最适合直接作为发布底稿：`index.en.1017.md`。** 结构、第一人称、技术链条和英文禁用 em dash 的要求完成得最均衡，但仍需删掉 `easy`、`simple` 等词，并补齐更新事实的来源链接。
- **英文最有人味：`index.en.v4p.md`。** “I have to own a mistake here”“I wasn't about to declare victory on gut feeling”这类句子最像个人博客；但它缺少部分步骤细节，且标题中有 em dash、正文出现 `simple`，不宜原样发布。
- **不建议直接发布任何一个单稿。** 最稳妥的成稿组合是：中文采用 `index.o55.2.md` 的叙事和证据链，按 `index.1017.md` 的克制程度收口；英文以 `index.en.1017.md` 为骨架，吸收 `index.en.v4p.md` 的个人失误和情绪细节。

## 评分口径

总分 100 分：

- `spec.md` 结构与章节对齐：20 分
- 第一人称、人味、博客感：25 分
- 证据链与推断边界：25 分
- 原理、命令、输出解释的完整度：20 分
- 去 AI 味、语言和排版：10 分

外部 Writing Guidelines 只作为风格参考。它要求 `meta.contentType`、计划、目标和受众等字段，但当前仓库的 `AGENTS.md` 与 `spec.md` 没有要求这些 front matter 字段，因此不把它们作为硬性扣分项；正文的主动语态、短句、少套话、禁用 em dash 等仍纳入评估。

### 中文逐篇评语

#### 1. `index.o55.2.md`：推荐作为中文叙事底稿

优点：

- 开头直接给观点，随后自然进入舍友机器的事故，没有冷冰冰的“问题—方案—结论”模板感（`index.o55.2.md:16-36`）。
- 把关键弯路写清楚：换错外来 `SECURITY`、`SYSTEM` 挂载后忘记 `reg unload`、后来才转向 Agent（`index.o55.2.md:274-370`）。这正好命中 `spec.md:86-90` 的要求。
- 对 `0xd000014c`、`0xd0000043`、SID、`DPAPI_SYSTEM`、`seq1/seq2` 和日志链的解释都有证据承接，没有只贴命令（`index.o55.2.md:233-325`、`index.o55.2.md:423-506`）。
- 受控实验矩阵把“脏标志致命”与“旧日志是否必须隔离”分开验证，技术结论清楚（`index.o55.2.md:490-506`）。
- 对删除休眠文件、更新残留和最终复查交代了前置条件，没有把删除动作写成无条件教程（`index.o55.2.md:578-691`）。

问题：

- 仍有 `我们`、`不是……也不是……` 等句式，和 `spec.md:92-95` 的去 AI 味规则冲突；应通读全文统一为“我”，并重点处理 `index.o55.2.md:705` 的假对比句式。
- “暂停更新 1000 周”属于高风险建议，应明确写成“延长系统自带暂停窗口”，不能让读者理解成永久禁用；同时保留“暂停期间收不到安全补丁”的提醒（`index.o55.2.md:704-749` 已有基础说明，但建议再前置一次风险）。
- 文章仍然偏长。`index.o55.2.md:649-691` 的四层验证可以保留，但应删掉部分重复的状态清单，让真正的结论更突出。
- 标题 `### BBI 和那个孤儿驱动`、`### 删掉休眠文件和更新残留` 与 `spec.md:72-77` 给出的标题不完全一致。不是硬伤，但最终稿最好统一成规划标题。

#### 2. `index.1017.md`：最适合发布前收敛

优点：

- 五个二级标题和全部关键三级标题完整，且中英文有对应版本（`index.1017.md:16-114`、`index.1017.md:265-743`）。
- 对证据和猜测的边界处理最好：明确写出“最合理的解释是推断，不是直接证据”（`index.1017.md:414`），符合 `spec.md:117`。
- 真实误操作写得清楚：`SYSTEM` 可加载、忘记卸载导致单次 `0xd0000043`、外来 `SECURITY` 造成假修复（`index.1017.md:292-349`）。
- 解释了为什么官方镜像不能直接覆盖本机 Hive，也解释了镜像的正确用途（`index.1017.md:481-509`）。
- Windows 更新批评保留了 Microsoft Learn、Windows Latest、BleepingComputer、ZDNET 等链接（`index.1017.md:701-703`），满足 `spec.md:121` 的方向。

问题：

- `index.1017.md:507-509` 使用“我们后来”“受控验证”等表达，第一人称不够统一；改成“我后来”或明确说明“Agent 做了什么、我批准了什么”。
- `index.1017.md:619-640` 的复查细节很硬核，但缺少一句面向新手的结论，可在表格前补一句“这些检查证明修改只影响头部状态，不等于证明所有 Windows 功能都正常”。
- `index.1017.md:18-26` 的前言略像观点宣言，建议减少“我建议至少 200 到 300 GB”的绝对口吻，改成“按这台机器的使用方式，我会给 C 盘留……”。

#### 3. `index.4a.md`：证据最全，但需要去 AI 味和删冗余

优点：

- 可以作为作者口吻和事故原始顺序的素材，不应作为候选成稿排名靠前的版本。

#### 1. `index.en.1017.md`：英文发布首选

#### 2. `index.en.4a.md`：最完整，但不是最好的标题底稿

- 文章过长，并且保留了 Markdown `---` 分隔线（`index.en.4a.md:34`、`638`、`838`）。它适合提取技术段，不宜整篇直接上线。

#### 3. `index.en.v4p.md`：最有人味，但要补技术动作

#### 4. `index.en.k3.md` / `index.en.k31p.md` / `index.en.o55.md`

- `index.en.k31p.md` 与 `index.en.o55.md` 文件内容完全相同，属于重复候选；保留一个即可。

- `index.en.k3.md:560` 对微软工程质量作出宽泛判断，超出本文证据；应改成具体 KB、具体影响、具体来源。

#### 5. `index.en.38f.md`：不建议作为英文底稿

- 技术内容完整，英文句子本身也较通顺。
- 但 `we`、`our` 从前半篇就大量出现，例如 `index.en.38f.md:56`、`102`、`133`、`291`，削弱了“我帮舍友修电脑”的作者视角。
- `index.en.38f.md:23` 使用 em dash，且全文保留 `---` 分隔线；不符合 `spec.md:95` 和外部写作规则。
- 叙事更像 AI Agent 与作者共同提交的调查报告，不像博客作者的复盘。

## 发布前必须处理的问题

1. **把因果关系降级为推断。** 已知事实是 C 盘曾经 0 字节、`SECURITY` 加载失败、Hive 的数据区结构完好、序列号未追平。不能写成“已证明 Windows Update 正在写 SECURITY 时把它截断”，除非再提供直接日志证据。`index.1017.md:414` 的写法最稳。
2. **不要把外来 `SECURITY` 当作修复方案。** 必须明确先备份原件，校验 `PolAcDmN`、`PolAcDmS`、`DPAPI_SYSTEM`，在副本上 `reg load`，最后才写回。`index.o55.2.md:563-602` 和 `index.en.4a.md:670-730` 可作为步骤来源。
3. **修正 BitLocker 的绝对化表述。** “没有 Key Protector”与“当前输出显示完全解密”是证据；不能泛化成“本地账户一定不会有恢复密钥”或“后续不会再锁盘”。
4. **解释 `manage-bde -off` 的实际作用。** 对已完全解密的卷，它不会“解除一个已经存在的加密”；文章应写成状态确认和保险动作，不要承诺它能消除所有 TPM 风险。
5. **把“暂停更新”写成可逆的风险选择。** 必须同时说明暂停期间不接收安全补丁、未来版本可能忽略这些注册表值、空间清理和定期手动更新仍是根治手段。
6. **删掉 AI 式结尾和绝对形容词。** 例如“这条线索断了”“改完只差 2 个字节”“绝对安全”“100% 无损”“微软 QA 崩了”等。保留数字和证据，删掉情绪化判断。
7. **统一中英文技术名词。** 中文第一次出现时解释 Hive、LCU、CBS、DPAPI、ESP；英文第一次出现时保留全称。不要在不同版本间切换 `Boot Environment Infrastructure`、`Background Broker Infrastructure` 而不说明来源不确定性。
