## 2. 关键证据

### 2.1 蓝屏转储(唯一一份)

`C:\Windows\Minidump\110226-9312-01.dmp`(6,662,433 B,PAGEDU64)

```
BugCheckCode = 0x74  (BAD_SYSTEM_CONFIG_INFO)
P1 = 0x2                 ← hive 加载失败
P2 = 0xffff94869fbd2940
P3 = 0x1
P4 = 0xffffffffc000014c  ← STATUS_REGISTRY_CORRUPT
崩溃时间(header) = 2026-11-02 07:36:19 UTC = 15:36 +08
内嵌字符串(逐字节核对):ASCII `HiveLoadFromomFile`(内核拼接残留)+ `status`;宽字符 `<SECURITY`(注意是 `<>` 不是 `\`)。
```

即:**内核在 boot 阶段加载 SECURITY 失败**,不是磁盘/驱动/引导问题。

### 2.2 hive 序列号 vs 日志序列号(核心机理)

| 文件 | 大小 | 序列 | 结论 |
|---|---|---|---|
| SECURITY(原始,现于 CorruptBak) | 65,536 | **17965 / 17964** | 脏(seq1≠seq2) |
| SECURITY.LOG1 | 49,152 | **208 / 208** | 2022 年的陈旧日志 |
| SECURITY.LOG2 | 8,192 | **17963 / 17963** | 比 hive 落后 2 个事务 |
| SECURITY(当前 C:,外来) | 65,536 | 210 / 210 | 干净,但**不是本机** |

内核规则(经第 9.2 节 s1/s2/s3/t1 四组实验校正):**只要 `seq1 != seq2` 就判脏,脏 hive 一律拒绝加载**——不论日志是否存在、是否为零字节、是否可重放。日志重放本身这次没有单独构造验证,但 `reg load` 在 hive 干净时对陈旧日志完全不敏感(用例 j),说明本机这条路径上日志不参与判定。`208`、`17963` 都不满足重放条件,属于次要因素;真正致命的是脏标志本身。

**受控实验矩阵(全部在 D:\_fix\mx 下用副本完成,未动 C:)**

| 用例 | hive | 附带日志 | 结果 |
|---|---|---|---|
| a | 原始(脏 17965/17964) | LOG1(208)+LOG2(17963) | **LOAD_FAIL**(复现蓝屏) |
| b | 原始 + 引擎重写(17966) | 同上 | LOAD_OK |
| c | 原始 + 引擎重写 | 无 | LOAD_OK |
| d | 外来 hive | 本机日志 | LOAD_OK |
| e | 外来 hive | 无 | LOAD_OK |
| f | 外来 hive(seq203 副本) | 本机日志 | LOAD_OK |
| g | 原始(脏) | **无日志** | **LOAD_FAIL**(脏标志本身即致命) |
| h | 原始(脏) | 仅 LOG2(17963) | **LOAD_FAIL** |
| i | **原始 + 仅改 2 字段**(seq2=seq1、重算校验和) | 无 | **LOAD_OK** |
| j | 同上(最小补丁) | LOG1+LOG2 原样保留 | **LOAD_OK** |

→ 结论:**只要清掉脏标志,即使陈旧日志原样留着也能加载**(用例 j),因此修复面只有 2 个字段。

> 第 9.2 节用 s1(脏、无日志)、s2(脏、0 字节日志)、t1(脏、seq2 再减 2)三组实验补齐了这条规则的边界:**脏标志 = 硬失败**,与日志无关。

## 4. 为什么"用镜像覆盖 hive"这条路走不通

镜像(Index 1,家庭中文版)内 `Windows\System32\config\` 是**通用安装态**,与本机机器绑定数据无关:

| hive | 镜像内 | 本机 | 后果 |
|---|---|---|---|
| SYSTEM | 9,175,040 B / **661 服务** / ComputerName = `MINWINPC` | 32,243,712 B / **846 服务** / `LAPTOP-VQSR6OMV` | 丢失全部驱动服务、Enum 设备树 → INACCESSIBLE_BOOT_DEVICE |
| SAM | **8,192 B**(空库) | 131,072 B / 5 个账户 | 账户全丢 |
| SECURITY | **8,192 B**(空) | 65,536 B | LSA 机密全丢,DPAPI 数据不可恢复 |
| SOFTWARE | 66,584,576 B | 117,440,512 B | 全部已装软件注册信息丢失 |
| DEFAULT | 32,768 B | 6,029,312 B | 用户配置模板丢失 |
| BBI | 8,192 B(空队列) | 1,310,720 B | **可以用,这是唯一适合从镜像取用的 hive** |

镜像的**正确用途**:

1. 作为**比对基线**——已完成(服务基线、驱动基线、SYSTEM 关键键基线、BBI 有效性基线)。
2. 提供**干净的 BBI**(P0-2 的备选方案)。
3. 若后续需要 `DISM /RestoreHealth`,作为 `/Source:D:\_fix\mount\Windows\winsxs` 的来源。
4. 作为**兜底重装**的安装源。

镜像**不能**做的事:

- 不能替换 SYSTEM/SAM/SOFTWARE/SECURITY/DEFAULT。
- 不能就地升级修复:镜像 22631.2861 < 已装 22631.5768。
